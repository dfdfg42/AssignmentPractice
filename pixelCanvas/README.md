# pixelCanvas (미완성)

16×16 공용 픽셀 캔버스 서버. 유저가 픽셀을 하나씩 칠하고, 보유 픽셀 수로 랭킹을 매기는 문제다.

> **미완성 상태로 올린 코드다.** 컨트롤러는 빈 껍데기이고 저장소 로직은 중간에 끊겨 있어 **컴파일되지 않는다.** 코드 안의 주석은 당시 설계 메모 그대로 남겼다. 아래 지문은 코드와 메모에서 역추적해 다시 쓴 것이라 원본과 다를 수 있다.

## 문제 지문 (재구성)

**도메인**:

- 유저: `uuid`, 닉네임, 관리자 여부.
- 픽셀: 좌표 `(x, y)` (16×16), 색상, 마지막 갱신 시각, 칠한 유저.
- 한 번도 칠해지지 않은 픽셀은 검은색이고 유저 정보가 비어 있다.

**규칙**:

- 유저는 픽셀 하나를 칠한 뒤 1분이 지나야 다시 칠할 수 있다 (유저별 쿨타임).
- 관리자는 쿨타임이 없다. 단, 관리자가 칠한 픽셀은 소유 유저와 갱신 시각을 기록하지 않는다.
- 픽셀은 마지막에 칠한 유저의 소유가 된다.

**API**:

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/pixelUpdate` | 유저가 좌표에 색을 칠한다. 쿨타임 중이면 거부 |
| GET | `/pixelInfo` | 좌표의 색상·소유 유저·갱신 시각 |
| GET | `/allPixel` | 16×16 전체 상태 |
| GET | `/ranking` | 보유 픽셀 수 상위 100명. 관리자 제외 |

**동시성**: 여러 유저가 같은 픽셀을 동시에 칠할 수 있으므로 갱신은 원자적이어야 한다.

## 구현 현황

| 구성 요소 | 상태 |
|---|---|
| `Pixel`, `PixelInfo`, `User` | 값 객체 완성 (`Pixel`은 `equals/hashCode`로 맵 키로 사용) |
| `PixelRepository.put` | 쿨타임 판정 로직이 뒤집혀 있고(1분 지났거나 관리자면 거부하는 형태), 첫 갱신 유저의 `lastUpdate`가 null인 경우 미처리 |
| `PixelRepository.get` | 존재하지 않는 setter 호출 등 미완 |
| `PixelRepository.getRank` | 16×16 순회 도중 끊김 |
| `PixelController` | 네 엔드포인트 모두 빈 응답만 반환 |
| 16×16 초기화 | 메모만 있고 구현 없음 |

## 남긴 설계 메모

- 저장소는 `ConcurrentHashMap<Pixel, PixelInfo>`, 유저별 마지막 갱신 시각은 `ConcurrentHashMap<uuid, Instant>`, 유저 조회는 `ConcurrentHashMap<uuid, User>`.
- 픽셀 갱신은 `compute()`로 원자성 확보. 유저 쿨타임 갱신과 픽셀 갱신 사이의 경쟁은 해결 못 한 채 남음.
- 랭킹은 전체 픽셀을 순회해 uuid별 개수를 세고 정렬하는 방식으로 구상.
